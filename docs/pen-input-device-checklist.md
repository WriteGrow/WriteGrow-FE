# 펜 입력 실기기 검증 체크리스트

`docs/frontend-plan.md` Phase 1 완료 기준을 실제 태블릿(애플펜슬 / S펜)에서 확인하기 위한 체크리스트다. 코드로는 검증할 수 없어 사용자가 직접 실기기에서 테스트한 뒤 이 문서에 결과를 채워 넣는다. 대상 컴포넌트: `src/lib/pen/PenCanvas.tsx`.

## 사용법

각 항목을 실기기에서 테스트한 뒤 `- [ ]`를 `- [x]`로 바꾸고, 비고 칸에 기기 기종·OS·브라우저와 관찰한 내용을 적는다.

---

### 1. 필압 반영

- 관련 코드: `handlePointerDown`(`PenCanvas.tsx:72-86`) / `handlePointerMove`(`PenCanvas.tsx:88-98`)가 `e.pressure`를 스트로크 각 점에 기록하고, `getStroke(stroke, { size: 6 })`가 이를 굵기에 반영한다.
- 확인 방법: 펜을 세게 눌러 그은 획과 살짝 눌러 그은 획의 굵기가 눈에 띄게 달라지는지 확인. 개발 모드에서 화면 하단 진단 패널의 압력 수치가 누르는 힘에 따라 실시간으로 변하는지 함께 확인.
- [x] 통과 여부: 갤럭시탭에서 확인 완료.
- 비고: 세게/살짝 누른 획의 굵기 차이가 실제로 반영됨.

### 2. 팜 리젝션 / 스타일러스 전용 입력

- 관련 코드: `handlePointerDown`(`PenCanvas.tsx:72-75`)에서 `stylusOnly`가 켜져 있으면 `e.pointerType === 'touch'`인 이벤트를 폭(width)과 무관하게 항상 무시. S펜/애플펜슬은 `pointerType: 'pen'`으로 들어오므로 손가락(`'touch'`)과 명확히 구분된다. `PenWrite.tsx`의 "스타일러스 전용" 스위치(기본 ON)로 아동/보호자가 직접 끄고 켤 수 있다.
- 확인 방법: 손바닥을 캔버스 위에 얹은 채로 펜으로 글씨를 써서, 손바닥 접촉이 획으로 그려지지 않는지 확인. 스위치를 끄면 손가락으로도 그려지고, 다시 켜면 손가락 입력이 무시되는지 확인.
- [x] 통과 여부: 1차로 폭 기반(`e.width > 20`) 방식이 갤럭시탭 S펜 실기기 테스트에서 손가락 입력을 걸러내지 못함을 확인 → `pointerType === 'touch'` 기준으로 수정하고 온/오프 스위치를 추가한 뒤 **갤럭시탭에서 재검증 완료**(2026-08-15).
- 비고: 갤럭시탭 + S펜 기준. 다른 기종(아이패드+애플펜슬 등)에서는 아직 미검증.

### 3. 스크롤 간섭

- 관련 코드: `svg`에 `touch-none` 클래스(`PenCanvas.tsx:116`) 적용.
- 확인 방법: 펜 작성 화면(`/child/write/pen`)에서 캔버스 위를 손가락/펜으로 그을 때 페이지가 스크롤되지 않는지 확인. 반대로 이전 글 목록(`/child/posts`) 등 캔버스가 없는 화면에서는 손가락 스크롤이 정상 동작하는지 확인(회귀 없는지).
- [x] 통과 여부: 갤럭시탭에서 확인 완료 — 해결됨.
- 비고: 캔버스 위 그리기 중 페이지 스크롤 없음, 다른 화면의 손가락 스크롤도 정상.

### 4. Scribble 간섭 (iPad) — 스코프 제외

- 확인 방법: iPad + Apple Pencil에서 캔버스 위에 시스템 Scribble(손글씨 → 텍스트) 제스처가 끼어들어 오작동하지 않는지 확인. 캔버스 밖의 `input`/`textarea`(예: `OcrConfirm.tsx`, `Hint.tsx`의 답 입력창)에서는 Scribble이 정상적으로 텍스트를 입력해주는지도 함께 확인.
- [x] 통과 여부: **제외 — iPad 실기기가 없어 검증 불가하며, 사용자가 이번 s2 완료 범위에서 제외하기로 결정함(2026-08-16).**
- 비고: iPad + Apple Pencil 실기기가 생기면 별도로 재검토.

### 5. 미지원 기기 폴백 경로

- 관련 코드: 현재 자동 감지 로직은 없음 — `WriteStart.tsx`의 "키보드로 쓰기" 버튼(`WriteStart.tsx:63-69`)이 유일한 대체 경로다.
- 확인 방법: 펜/터치 입력이 불안정하거나 Pointer Events를 지원하지 않는 환경(예: 구형 브라우저, 마우스만 있는 데스크톱)에서 "키보드로 쓰기"를 선택했을 때 글쓰기 흐름이 끊김 없이 이어지는지 확인. 자동 감지 후 리다이렉트가 아니라 아동이 직접 선택해야 하는 구조임을 인지하고, 이 UX가 충분한지 별도로 판단.
- [x] 통과 여부: 자동 감지 로직 없이 "키보드로 쓰기" 버튼으로 대응하는 현재 구조로 충분하다고 판단함.
- 비고: 별도 자동 감지/폴백 로직 추가는 불필요.
