# 초등 AI 문해력 코치 — 프론트엔드 착수 계획

아동 글쓰기·교정(s2)과 보호자 리포트·검토(s3)를 목 백엔드 위의 PWA로 먼저 세운다. 학습 순환이 실제로 도는지, 그리고 태블릿 펜 입력이 성립하는지를 백엔드 없이 검증하는 것이 이 단계의 목적이다.

## 1. 범위 — 무엇을 만들고, 무엇을 미루는가

## 2. 기술 스택 — React + PWA

React Native를 검토했으나 채택하지 않았다. 펜 입력의 필압·기울기·호버는 표준 Pointer Events로 이미 브라우저에서 지원되고, RN으로 가도 PencilKit과 S Pen SDK를 플랫폼별로 브릿징해야 해 "하나의 코드베이스"라는 RN의 존재 이유가 무너진다.

- **아동 카테고리 심사 회피** — 아동 대상 앱은 스토어 심사에서 SDK 제약과 지연 리스크가 크다. 웹은 이 규제를 받지 않는다.
- **MDM 관리형 기기** — 학교·방과후 태블릿은 앱 설치가 막힌 경우가 흔하다. PWA 홈 화면 추가로 우회한다.
- **저빈도 사용자의 마찰** — 보호자는 주 1회, 교사는 가끔이다. 앱 설치를 강제하면 이탈한다. 링크가 낫다.

> **감수한 트레이드오프**
> iOS의 푸시 알림과 백그라운드 동기화는 네이티브보다 제약이 크고, 스토어 발견성은 포기한다. 푸시가 핵심 리텐션 전략이 되는 시점에는 재검토 대상이다.

| 영역 | 선택 | 근거 |
|---|---|---|
| 프레임워크 | React + TypeScript (Vite SPA) | 대시보드형 앱이고 SEO가 불필요하다. Next.js보다 가볍고 배포가 단순하다. |
| 손글씨 캡처 | Pointer Events + Canvas, perfect-freehand | 필압·기울기 처리와 획 보정. |
| PWA | Web App Manifest + Service Worker | 태블릿 홈 화면 설치, 오프라인 작성 큐잉. |
| 서버 상태 | TanStack Query | 오류 분석·리포트·대시보드 등 잦은 fetch의 캐싱과 재검증. |
| 클라이언트 상태 | Zustand | 힌트 진행 단계, 입력 방식 등 순수 로컬 상태. |
| 차트 | Recharts / visx | 주간 리포트 추이. 교사 대시보드의 우선순위 비교까지 확장 가능. |
| 스타일링 | Tailwind CSS + 자체 디자인 시스템 | 저학년 아동용 접근성 커스터마이징이 필요하다. |
| 인증·권한 | 역할 기반 라우트 가드 | 아동·보호자·교사·기관 관리자 4개 역할 `R-BRBVSX`. MVP에서는 앞 2개만 실사용. |
| 목 백엔드 | MSW + 시드 데이터 | 네트워크 계층에서 가로채므로 실제 API 연동 시 코드 변경이 없다. |

### 저학년 접근성 토큰 — 초기값 제안 (참고용)

아동 화면은 성인 기준보다 여유를 둔다. 아래는 디자인 시스템의 출발점이며 실기기 확인 후 조정한다.

- 터치 타깃 `56px`
- 본문 `20px`
- 대비 `4.5:1` 이상
- 한 화면에 제시하는 교정 대상 `최대 2개` (`R-GLTURC`)

## 3. 화면 지도 — 와이어프레임 노드 ↔ 라우트

라우트를 유저플로우 노드에 1:1로 대응시킨다. 문서와 코드가 같은 주소를 쓰게 되어, 나중에 화면이 바뀌어도 어느 노드가 영향을 받는지 바로 추적된다.

| 노드 | 화면 | 라우트 | 다음 |
|---|---|---|---|
| `n11` | 아동 홈 | `/child` | 작성 · 목록 |
| `n14` | 글쓰기 작성 (주제·방식 선택) | `/child/write` | 펜 → 분기 / 키보드 → 분석 |
| 신설 | 펜 작성 | `/child/write/pen` | OCR 확인 |
| `n16` | OCR 텍스트 확인 | `/child/write/ocr` | 분석 로딩 |
| `n20` | 오류 분석 로딩 | `/child/write/analyzing` | 대상 있음 → 힌트 / 없음 → 결과 |
| `n22` | 자기교정 힌트 | `/child/write/hint` | 성공 → 결과 / 실패·다음 힌트 → 자기 자신 |
| `n27` | 교정 결과 | `/child/write/result` | 아동 홈 |
| `n28` | 이전 글 목록 | `/child/posts` | 글 상세 |
| `n31` | 글 상세 열람 | `/child/posts/:postId` | — |
| `n33` | 보호자 홈 | `/parent` | 주간 리포트 |
| `n36` | 주간 성장 리포트 | `/parent/children/:childId/report` | 개별 글 · 검토 |
| `n39` | 글 수정 전후 열람 | `/parent/children/:childId/posts/:postId` | — |
| `n42` | 낮은확신도 오류 검토 | `/parent/children/:childId/review` | — |

### 프로젝트 구조

```
src/
  app/              라우터(역할 가드) · queryClient · 프로바이더
  features/
    writing/        s2 — 작성 · 펜 · OCR · 분석 · 힌트 · 결과 · 기록
    report/         s3 — 보호자 홈 · 주간 리포트 · 전후 열람 · 검토
  lib/
    pen/            Pointer Events 캔버스 · perfect-freehand · 획 모델
  components/ui/    저학년 접근성 프리미티브
  mocks/            MSW 핸들러 · 시드(아동 2명 · 글 15편 · 오류 프로필)
  stores/           zustand — 힌트 단계 · 입력 방식
```

## 4. 진행 계획 — 네 단계

### Phase 0 — 기반

- Vite + React + TypeScript, Tailwind, 라우터, TanStack Query, Zustand
- PWA — manifest와 service worker, 태블릿 홈 화면 설치 확인
- MSW 핸들러와 시드 데이터 — 아동 2명, 글 15편, 오류 프로필
- 디자인 토큰 — 터치 타깃·본문 크기·대비, 아동/보호자 두 레이아웃 셸
- 역할 가드 골격과 개발용 역할 스위처

**완료 기준** — `/child`와 `/parent`가 각자 레이아웃으로 뜨고, 목 API 응답이 Query를 통해 화면까지 들어온다.

### Phase 1 — 펜 입력 스파이크

- `/child/write/pen` 캔버스 — Pointer Events + perfect-freehand
- 필압·기울기·pointerType을 실시간으로 보여주는 진단 패널 (개발 전용)
- 실기기 확인 — 필압 반영, 스크롤 간섭, Scribble 간섭, 팜 리젝션

**완료 기준** — 태블릿에서 필압이 반영된 획이 끊김 없이 그려지고, 손바닥·스크롤·Scribble 어느 것도 그리기를 방해하지 않는다. 미지원 기기 폴백 경로가 동작한다.

### Phase 2 — s2 아동 글쓰기·교정 (9 화면)

- 홈 → 작성 → 펜/키보드 → OCR 확인 → 분석 로딩 → 힌트 → 교정 결과
- 이전 글 목록과 글 상세
- 힌트 단계 전환, 재시도, 도움 요청 상태 — 가장 얇게 그려진 화면이라 설계 여지가 크다

**완료 기준** — 목 데이터로 작성·발견·수정·성장 확인의 학습 순환이 한 바퀴 끊김 없이 돈다.

### Phase 3 — s3 보호자 리포트·검토 (4 화면)

- 보호자 홈, 주간 성장 리포트(추이 차트)
- 글 수정 전후 열람, 낮은확신도 오류 검토
- 확정 오류와 낮은 확신도 후보의 시각적 구분 (`F-IEQBIY`)

**완료 기준** — 리포트에서 개별 글과 검토 화면까지 도달하고, 낮은 확신도 후보가 확정 오류로 집계되지 않는다.

> **미확정**
> s2를 먼저 끝내고 s3를 얹는 순서를 전제로 썼다. 두 영역은 사용자·디바이스·상호작용 성격이 겹치지 않아 레이아웃 시스템이 사실상 둘이다. 동시 진행을 택하면 Phase 2와 3이 합쳐지고 펜 검증이 뒤로 밀린다.

## 5. 범위 밖 — 이 단계에서 손대지 않는 것

- 백엔드 API, 데이터베이스, 인증 서버 — 전부 MSW 목으로 대체
- 실제 OCR 엔진 연동 (`F-WLRFZD`)과 AI 오류 분석 (`F-QZXONT`)
- s1 인증·온보딩, s4 보호자 설정·동의 관리, s5 교사·기관 대시보드 — 화면 13개 미제작
- 푸시 알림 — PWA의 iOS 제약을 감수한 결정에 포함된다
- Spec 작성 — 현재 0개. 개발 착수와 병행 가능하나 이 문서의 범위는 아니다
